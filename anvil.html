Anvil

A miner you can actually read, built to teach — and it still does real work.

Anvil is a native Go multi-algorithm CPU/GPU cryptocurrency miner with an embedded web control panel. It exists first as a learning tool — a from-scratch implementation of stratum, share submission, difficulty handling, midstate hashing, and OpenCL GPU kernels that's small enough to actually read end-to-end — and second as something you can point at a real pool and mine with, because every line of that logic is live, working code.

01 What Anvil actually is

Most miners you can download are either closed-source binaries or large, mature codebases that are hard to read in one sitting. Anvil is the opposite: a single self-contained Go program, written to be understood.

📖

A learning tool first

Built to understand the full stack a miner needs: stratum protocol handling, vardiff, extranonce rolling, midstate precomputation, coinbase construction, and raw OpenCL GPU calls — without a wrapper hiding any of it.

⚒️

...that does real work

Every one of those pieces is live, not a toy stub. Point it at a real pool with a real payout address and it hashes, submits shares, and gets paid like any production miner — the "learning tool" framing is about transparency, not fidelity.

🔩

Zero external dependencies

Compiles to one self-contained binary — web panel assets, icons, and GPU kernels embedded via go:embed. No CGO needed on Windows; it binds the OS's own OpenCL.dll at runtime.

02 Algorithms & hardware

Five algorithm implementations, each hand-written rather than vendored — this is most of what there is to learn from.

WPXF (CapStash)

GPU / CPU · ~130–180 MH/s on an RX 580

Whirlpool-512, XOR-folded. 50% midstate precomputation + LDS lookup tables on GPU.

SHA-256d (BTC/BSV/Caps)

GPU / CPU · ~180–250 MH/s on an RX 580

Double SHA-256 with midstate, a 16-word rolling window, and round-60 early-out.

VerusHash 2.2

CPU · ~15–18 MH/s on a Ryzen/Core i7

Native AMD64 assembly — AESENC, PCLMULQDQ, PMULHRSW — no generic fallback path.

Scrypt (LTC/DOGE)

GPU / CPU · ~350–650 kH/s on an RX 580

N=1024, lookup-gap 2 (64KB/thread), diagonal uint4 Salsa20/8 on GPU.

RandomX (Monero)

CPU · ~1.0–2.0 kH/s multi-core

Pure-Go RandomX VM talking Monero JSON-RPC 2.0 — no cgo, no librandomx binding.

Heterogeneous dual-mining

GPU + CPU, simultaneously

Mine WPXF/SHA256d/Scrypt on the GPU while the CPU independently mines VerusHash or RandomX — two stratum connections, two job pipelines, isolated difficulty tracking.

Why this is worth reading, not just running: the GPU path is pure-Go on Windows (no MSYS2/MinGW/cgo — it calls OpenCL.dll directly via syscall.NewLazyDLL), and every algorithm's hot path shows the real optimization: midstate hoisting, precomputed round constants, LAN auto-discovery for clustering multiple rigs. It's the kind of code you can step through in a debugger and come away actually understanding stratum mining.

03 Embedded web control panel

Everything is controllable from http://localhost:8099 without touching the command line again after first launch.

🖥️

Live console feed

Realtime stratum jobs, difficulty updates, and accepted/rejected shares streamed straight from the engine — the only log sink once the windowless build hides the terminal.

🎛️

One-click coin presets

Click a coin logo to auto-fill algorithm, pool, and sane defaults — CapStash, Verus.io, Luckpool, LitecoinPool.org, SupportXMR.

📡

LAN auto-discovery

UDP beacon discovers other Anvil rigs on the same network and aggregates total farm hashrate automatically — no config needed.

📊

Realtime hashrate chart

Local rig rate, LAN farm total, and share efficiency, all on one canvas chart that updates live.

Default panel login: admin / anvil26 — change panel_pass in config.json before exposing the panel beyond your own LAN. The panel binds 0.0.0.0:8099 by default.
